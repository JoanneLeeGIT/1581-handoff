# 營運概況月報管理 原型

花蓮公車客運智慧管理系統（1581 擴充模組）「營運概況線上填報與檢核」的可互動原型。純前端、Bootstrap 5、資料存在瀏覽器（localStorage）。**全部是假資料**，不可放入真實業者資料。

規格與設計文件在 `../specs/001-operations-overview-reporting/`。

## 啟動

在 `prototype/` 資料夾執行：

```powershell
python -I -m http.server 8781
```

用 Chrome 或 Edge 開 `http://localhost:8781/`。不要直接雙擊 HTML 檔（要用 http 才能讀取示範資料）。首次載入需要網際網路（Bootstrap、Bootstrap Icons、SheetJS 從 CDN 載入）。

## 測試

在專案根目錄執行（Node 18 以上）：

```powershell
node --test "prototype/tests/*.test.js"
```

涵蓋狀態、版本、權限、服務模式、延人公里、匯出彙總、原報表版面（表頭合併儲存格、儲存格驗證、總計、鍵盤移動）七組純函式規則。

## 怎麼操作

頁面上方的黃色「原型工具列」：

| 項目 | 用途 |
|---|---|
| 角色 | 縣府交通科（可檢核）、唯讀單位、或某一家業者（只看得到自己）。取代登入 |
| 模擬今天 | 改日期可看到「開放填報」（1–10 日）與「逾期未繳」（11 日起）。預設是真實今天 |
| 重設示範資料 | 清除所有操作，回到初始假資料 |

建議的展示順序：業者角色填報當月 → 切縣府檢核（標待更新並寫備註）→ 切回業者更正重送 → 縣府標已完成 → 業者對已完成月份按「申請變更」直接修改送出（存成新版本）→ 縣府駁回（維持已完成，現行版本回到原版）、退回待更新或同意更正 → 縣府匯出業者別與路線別 → 切到「票證資料」分頁看各季上傳狀態，業者進入某季上傳 CSV／Excel。完整驗證情境見 `quickstart.md`。

示範業者共 7 家：5 家市區客運、2 家幸福巴士（1.0 與 2.0 各一）。2026-10 各自停在不同狀態，2026-11 全部是「開放填報」。

## 填報畫面怎麼用

填報與檢視畫面照原 Excel「營運概況表」排成寬表格（一條路線一列）。灰底是系統自動填寫、白底由業者填、深灰底是此路線不適用的組別（固定為 0）。Enter 往下一列、Tab 往右一格；延人公里儲存格左邊的小圖示可切換「系統計算／自行填寫」。上方「填寫說明」可展開原表的說明列。

## 已知待確認

- 延人公里公式「客運人數 × 月底營業里程 × 0.35」尚待縣府確認；公式文字與係數集中在 `js/passengerKm.js` 的 `FORMULA`，確認後把 `confirmed` 改為 `true`，「待確認」標籤就會消失。
- 「行動支付」欄位沒有資料來源，業者別匯出顯示「-」。
- 路線別「TPASS 版」變體不在本期範圍。
- 服務模式是否有「固定＋預約」並存的路線、幸福巴士的車輛情形與包車出租是否沿用市區客運欄位、預約班次的延人公里是否套用同公式，待縣府確認。

## 結構

```text
index.html / report.html      總覽矩陣、單一月報（填報或檢視）
tasks.html                    系統資訊 → 每月任務（各單位每月檢查清單；資料在 js/monthlyTasks.js）
js/status.js                  月份狀態與轉換規則（純函式）
js/versions.js                版本與差異比對
js/permissions.js             角色權限
js/serviceMode.js             路線服務模式與可填組別
js/passengerKm.js             延人公里（公式設定在此）
js/export.js                  業者別／路線別匯出彙總（申請變更中以原版本匯出）
js/ticket.js                  票證資料：每季上傳期限（季結束後下一個月 1–15 日）、狀態、資料筆數（純函式）
js/reportLayout.js            原報表版面：表頭合併儲存格、說明列、儲存格驗證、總計（純函式）
js/store.js, js/clock.js      localStorage 與模擬今天
js/ui/                        各畫面
data/seed.json                假資料種子
tests/                        自動化測試
```
